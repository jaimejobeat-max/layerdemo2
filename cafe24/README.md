# plusjun.com (카페24) 뉴예약 스킨 조각

지금 운영 중인 plusjun.com의 예약 게시판(뉴예약, `board_no=4`)에 붙이는 스크립트입니다. 이 폴더의 파일은 이 저장소 사이트에서 쓰이지 않고, 카페24 스킨에 직접 붙여 넣습니다. 원본을 git에 두려고 여기에 둡니다.

## `reservation-fields.js` — 입력칸으로 쓰는 예약 폼

글쓰기 폼(`/board/reservation/write.html`)을 **01 일정 / 02 대관 정보 / 03 예약자 정보 / 04 요청 사항** 네 묶음으로 다시 짭니다. 카페24 원래 입력칸(스튜디오 예약, 예약자/업체명, 이메일, 비밀번호)은 지우지 않고 해당 묶음 안으로 옮기기만 해서, 카페24에는 예전과 똑같이 전송됩니다. 본문 양식의 모든 항목과 **하고 싶은 말** 칸을 넣고, 본문 에디터는 숨깁니다. 일정 아래에는 고른 내용이 "선택한 일정" 한 줄로 요약됩니다. 고르거나 적는 대로 숨겨진 본문의 해당 줄이 채워지고, **예약하기**를 누르면 "신청 내용을 확인해 주세요" 창에 항목별 요약표와 지점 안내가 나오고, "등록될 글 원문 보기"를 펼치면 본문 전체를 볼 수 있습니다. 고객이 **이대로 예약하기**를 눌러야 카페24에 등록되고, **수정하기**를 누르면 폼으로 돌아갑니다. 본문을 숨기는 대신 지점별 안내(주차·위약금 등, 양식 아래쪽 줄)는 입력칸 아래 "지점 안내"에 보여 줍니다.

```
* 대관 날짜 : 2026년 11월 8일(일)            (여러 날: 2026년 11월 5일(목) ~ 2026년 11월 7일(토) (3일))
* 대관 지점 : LAYER 41                       (양식 그대로)
* 대관 파트 : A+C                           (또는 전체 대관 / 미정 (상담 후 결정))
* 대관 시간 : 10:00 - 15:00 (5시간)          (또는 미정 (협의))
* 대관 내용 : 사진 촬영, 영상 촬영 / 의류 화보
* 이용 인원수 : 8명
* 방문 차량수 : 없음                          (0대일 때)
* 업체명 : (맨 위 '예약자/업체명' 칸에서 복사)
* 담당자명 : …
* 연락처 : 010-…
* 이메일 : (맨 위 '이메일' 칸에서 복사)
* 입금자명 : …
* 하고 싶은 말 : (여러 줄 그대로, 입금자명 줄 바로 다음)
```

- 카페24에 저장되는 글은 예전과 같습니다(제목 = 지점, 본문 = 양식). 알림·슬랙·목록, 스태프가 글을 열어 보는 화면도 그대로입니다.
- 필수: 예약자/업체명, 날짜·파트·시간(각각 미정 선택지 있음), 연락처, 글 비밀번호, 개인정보·위약금 동의. 예약자명·비밀번호·동의는 카페24도 원래 확인하는 항목인데, 확인 창을 띄우기 전에 미리 확인합니다. 나머지는 선택입니다.
- 지점을 바꾸면 카페24가 본문을 새 지점 양식으로 바꾸고, 입력칸의 값과 하고 싶은 말은 새 양식에 다시 채워집니다.
- 입력칸이 비어 있으면 본문에 원래 있던 그 줄의 내용은 지우지 않습니다(값이 있으면 그 값이 들어갑니다).
- 입력칸 옮기기와 에디터 숨기기는 스크립트의 맨 마지막 단계라서, 중간에 멈추면 예전 폼 그대로 쓸 수 있습니다. 카페24 입력칸 중 하나라도 예상한 자리에 없으면 옮기지 않고 원래 위치에 둡니다.
- 디자인은 블랙 앤 화이트입니다(검정·흰색과 회색 입력칸만, 포인트 색 없음). 모든 스타일은 `#lr-fields`, `#lr-confirm` 안에만 적용돼서 페이지의 다른 부분에는 영향이 없습니다.
- 최소 대관 시간(홍대 2시간, 레이어 4시간)보다 짧으면 경고만 보여 주고 막지는 않습니다.
- 날짜·시간·파트 형식은 레이소다 스케줄 게시판 글(`api/reserve.js`의 `buildPost`)과 같아서, 나중에 스태프용 "캘린더로 보내기" 버튼이 그대로 읽을 수 있습니다.
- 입력칸에는 `name`이 없어서 카페24로 따로 전송되지 않습니다. 글 수정·답글 화면에서는 동작하지 않습니다.

### 스킨에 적용하기

**2026-10-30 라이브 적용됨.** PC 대표 디자인 "PLUSJUN 2017 - WCOWORKERS"의 `board/reservation/write.html`, 지점 선택 가드 스크립트 바로 아래에 아래 표시 사이로 들어가 있습니다.

```
<!-- lr-reservation-fields 2026-10-30 start -->
<script>
…reservation-fields.js 전체…
</script>
<!-- lr-reservation-fields end -->
```

1. 카페24 관리자 → 디자인 (PC/모바일) → 디자인 편집 → 화면명 검색 `write` → `/board/reservation/write.html`
2. 두 표시 사이의 `<script>` 내용을 이 파일로 통째로 바꾸고 저장합니다("모든 파일을 저장" 확인 창이 뜹니다). 가드 스크립트보다 뒤에 있어야 지점 미선택 안내가 먼저 뜹니다.
3. 저장 후 라이브 페이지에서 두 표시 사이 내용이 이 파일과 **한 글자도 다르지 않은지** 확인합니다(아래 주의 참고).

**되돌리기:** 두 표시 줄과 그 사이를 지우고 저장하면 예전 폼으로 돌아갑니다. 카페24 디자인 편집의 "히스토리"에도 이전 버전이 남아 있습니다.

**주의 (카페24 저장 시 변환):** 스킨을 저장하면 카페24가 백슬래시 두 개를 하나로 줄이고, 물음표 바로 뒤의 `>`를 `&gt;`로 바꿉니다. 그래서 이 파일에는 둘 다 들어가면 안 됩니다(정규식은 문자열이 아니라 `/…/` 리터럴로 씁니다). 고친 뒤에는 아래 명령이 아무것도 출력하지 않아야 합니다.

```bash
grep -nF -e '\\' -e '?>' cafe24/reservation-fields.js
```

2026-10-30 첫 적용 때 이 변환 때문에 줄 찾기 정규식이 깨져서 몇 분 만에 되돌렸고(그사이 들어온 글 없음), 위 규칙으로 고쳐 다시 적용했습니다. 스킨 HTML에서 `{$이름}`은 카페24 변수로 해석되므로 그 형태도 넣지 않습니다.

휴대폰·태블릿(880px 미만)에서는 스킨이 모든 textarea에 `min-height:320px !important`를 걸어 둬서, "하고 싶은 말" 칸은 `#lr-fields textarea`에 `!important`로 높이를 다시 지정합니다.

### 주차 안내 (지점별)

차량 칸 옆에 지점별 주차 안내가 작게 나오고, 적은 대수가 기준을 넘으면 "주차는 N대까지 가능해요. 나머지 차량은 인근 유료주차장을 이용해 주세요."로 바뀝니다(막지는 않음). `BRANCHES`의 `park`에서 지점마다 고칩니다.

- `text`: 차량 칸 옆에 보이는 안내 문구
- `max`: 이 대수를 넘으면 경고
- `days`: 요일별로 기준이 다를 때(`5` = 금, `6` = 토). 지금은 LAYER 7만 금·토 4대(교회 주차 불가)
- `park`가 없는 지점은 안내를 띄우지 않습니다.

숫자는 2026-10-30 기준 각 지점 양식의 주차 안내 줄에서 옮겼고, 양식에 안내가 없는 LAYER 57은 기본 5대로 정했습니다. 범위로 적힌 곳(LAYER 7 차고지 3~4대, LAYER 20 5~8대, 한남 2~3대)은 큰 쪽을 기준으로 잡았습니다.

### 지점·파트가 바뀔 때

`BRANCHES`의 키는 스킨 `<select name="subject">`의 `<option value>`와 글자까지 같아야 합니다. 지점을 추가하거나 이름을 바꾸면 세 곳을 함께 고칩니다: 카페24 관리자 고정 제목, 스킨 `<option>`, 이 파일의 `BRANCHES`. 파트 이름은 새 홈페이지 예약 폼(`reservation.html`)과 같은 이름을 씁니다.

## `preview-harness.js` — 실제 등록 없이 미리보기

라이브 글쓰기 페이지에서 개발자 도구 콘솔에 `reservation-fields.js`, 이어서 이 파일을 붙여 넣으면 확인 창의 **이대로 예약하기**까지 눌러도 등록되지 않고, 대신 "등록될 본문"이 오른쪽 아래에 뜹니다. 새로고침하면 원래대로 돌아갑니다.
